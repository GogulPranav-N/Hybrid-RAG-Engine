# Docker Documentation — Quick Reference

## What is Docker?

Docker is a platform for developing, shipping, and running applications inside containers. Containers are lightweight, portable, and self-sufficient environments that include everything needed to run an application: code, runtime, system tools, libraries, and settings.

## Installing Docker

Docker Desktop is available for macOS, Windows, and Linux. Install it from [docker.com](https://www.docker.com/products/docker-desktop/).

Verify installation:
```bash
docker --version
docker compose version
```

## Docker Images

An image is a read-only template used to create containers. Images are built from Dockerfiles and can be stored in registries like Docker Hub.

```bash
# Pull an image
docker pull python:3.11-slim

# List images
docker images

# Remove an image
docker rmi python:3.11-slim
```

## Docker Containers

A container is a runnable instance of an image. You can create, start, stop, move, and delete containers.

```bash
# Run a container
docker run -d --name my-app -p 8000:8000 my-image

# List running containers
docker ps

# Stop a container
docker stop my-app

# Remove a container
docker rm my-app

# View logs
docker logs my-app
```

## Dockerfile

A basic Python Dockerfile starts with a FROM python:3.11-slim base image, sets a WORKDIR, copies requirements and installs them with pip, copies the application code, exposes the port, and sets the CMD to run the application.

```dockerfile
FROM python:3.11-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

Build and run:
```bash
docker build -t my-app .
docker run -p 8000:8000 my-app
```

## CMD vs ENTRYPOINT

CMD provides default arguments for the container that can be overridden at runtime. ENTRYPOINT sets the main command that always runs. When both are used, CMD provides default arguments to ENTRYPOINT. Use ENTRYPOINT for the main executable and CMD for default arguments.

```dockerfile
# CMD only — can be overridden
CMD ["python", "app.py"]

# ENTRYPOINT only — always runs
ENTRYPOINT ["python", "app.py"]

# Combined — ENTRYPOINT is the command, CMD provides defaults
ENTRYPOINT ["python"]
CMD ["app.py"]
```

## Multi-Stage Builds

A multi-stage Docker build uses multiple FROM statements in a single Dockerfile. You use earlier stages to compile or build, then copy only the necessary artifacts to a final slim stage. This results in smaller production images by excluding build tools and intermediate files.

```dockerfile
# Build stage
FROM python:3.11-slim AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Production stage
FROM python:3.11-slim
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.11/site-packages /usr/local/lib/python3.11/site-packages
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0"]
```

## Docker Volumes

A Docker volume is a mechanism for persisting data generated by and used by Docker containers. Volumes are stored on the host filesystem and managed by Docker. They are used to persist database data, share data between containers, and survive container restarts.

```bash
# Create a volume
docker volume create my-data

# Mount a volume
docker run -v my-data:/app/data my-image

# List volumes
docker volume ls

# Inspect a volume
docker volume inspect my-data

# Remove a volume
docker volume rm my-data
```

Bind mounts vs volumes:
- **Volumes**: Managed by Docker, stored in Docker's storage area
- **Bind mounts**: Map a host directory to a container directory

## Docker Networking

Docker Compose creates a default network for all services defined in the compose file. Containers can communicate using service names as hostnames. You can also define custom networks to isolate groups of containers and control connectivity.

```bash
# Create a network
docker network create my-network

# Run containers on the same network
docker run --network my-network --name db postgres
docker run --network my-network --name app my-app
```

In the app container, you can connect to the database using `db` as the hostname.

## Docker Compose

Docker Compose is a tool for defining and running multi-container Docker applications. You use a docker-compose.yml file to configure services, networks, and volumes. It's useful when your application depends on multiple services like databases, caches, or message queues.

```yaml
services:
  web:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://db:5432/mydb
    depends_on:
      - db

  db:
    image: postgres:15
    volumes:
      - db-data:/var/lib/postgresql/data
    environment:
      - POSTGRES_DB=mydb
      - POSTGRES_PASSWORD=secret

volumes:
  db-data:
```

Common commands:
```bash
# Start all services
docker compose up -d

# Stop all services
docker compose down

# View logs
docker compose logs -f

# Rebuild and restart
docker compose up --build -d

# Scale a service
docker compose up --scale web=3
```

## .dockerignore

A .dockerignore file tells Docker which files and directories to exclude from the build context. This speeds up builds by not sending unnecessary files to the Docker daemon and prevents sensitive files like .env, .git, and node_modules from being included in images.

```
.git
.env
__pycache__
*.pyc
node_modules
.venv
*.md
docker-compose.yml
```

## Best Practices

1. **Use specific base image tags** — avoid `latest`
2. **Order Dockerfile instructions** by frequency of change (dependencies before code)
3. **Use multi-stage builds** to minimize image size
4. **Don't run as root** — add a non-root user
5. **Use .dockerignore** to exclude unnecessary files
6. **Set health checks** for production containers
7. **Use environment variables** for configuration
8. **Tag images semantically** (e.g., `v1.2.3`, not just `latest`)

```dockerfile
# Health check example
HEALTHCHECK --interval=30s --timeout=3s \
  CMD curl -f http://localhost:8000/health || exit 1
```
